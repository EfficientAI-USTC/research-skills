# 科研技能创建与改进

将具体科研经验转成能够重复使用的任务流程。先读目标仓库的 AGENTS.md、README.md、skills/README.md 与 CONTRIBUTING.md，并查找已有同类技能，确定是在原位置更新还是创建新目录。

## 明确任务

优先从当前对话提取技能目标、典型请求、输入材料、输出形式和使用环境。只询问会改变实现的缺失信息。已有技能更新时，先保留旧版本供比较，识别本次要解决的实际问题。

本仓库技能平级放在 skills/<skill-name>/，名称全仓库唯一。创建工具类技能时使用具体名称，避免与客户端内置技能重名。模拟审稿指以审稿人视角评审实验室自己的稿件。

## 编写技能包

- SKILL.md 头部写 name、description，metadata.version 使用带引号的三段版本号。首次创建从 0.1.0 开始；更新时按改动范围递增。作者信息仅在已知时填写。
- description 用简短文字说明能力和触发场景；与其他技能容易混淆时，补充边界。详细步骤放正文。
- 正文说明必要输入、关键决策、执行步骤和交付形式。根据任务选择顺序流程或条件分支，保留真正有用的领域经验。
- 长篇参考资料放 references/，在入口注明何时读取；输出模板放 assets/；重复且适合确定性执行的逻辑放 scripts/。按需要创建目录。
- 脚本路径相对于技能自身目录，说明工作目录或解析方式。使用用户当前 Python 环境；额外 Python 依赖放技能根目录 requirements.txt，并提供匹配的安装说明。
- 使用当前环境实际提供的工具。需要另一技能时说明依赖和缺失时的处理方式。EvoScientist 专用的工具名、EXPERT.md 和调用命令只有在目标环境明确支持时才引入。

## 试用与迭代

根据改动选择适量真实请求：正常使用、输入不完整，以及容易误触发的相邻任务。先写期望产出与判断依据，再运行。修改描述时重点观察是否选对技能；修改正文时重点观察产出是否解决任务。

需要比较效果时，使用相同输入分别运行新版本和旧版本；新建技能可与未加载该技能的运行比较。固定模型、材料和任务条件，记录输出差异、耗时与可获得的用量。主观写作效果结合使用者反馈，不只依赖分数。

运行记录放任务临时目录，包含请求、输入出处、实际输出、问题和改进点。未运行的场景明确列为待试用。没有自动评测工具时，用人工试用推进；只有运行器确实存在时才引用其命令。

根据具体失败修改最相关的描述、步骤或资源，再复跑受影响的场景。避免针对单条样例堆叠通用规则。用户仅要求小幅修改时，完成对应检查即可。

## 完成更新

检查 YAML 可解析、name 与目录名一致、相对链接可达、模板占位已替换。新增或修改脚本时运行代表性输入。仓库有现成校验命令时使用实际命令。

同步根 README 和 skills/README.md 的入口与用途，按需要更新相关流程图。交付时说明改动、已运行的试用和剩余问题；提交或推送沿用用户对当前任务的授权。
